## Задание 1. `const` и `constexpr`

### Что просят
Есть 4 варианта одной строки. Нужно понять, в каких из них `Pi` — **константа этапа трансляции** (то есть значение известно уже при компиляции, до запуска программы).

### Код
Во всех четырёх файлах одно и то же, меняется только строка с `Pi`:

```cpp
double x = 0;
const     auto Pi = acos(0) * 2;   // v1
constexpr auto Pi = acos(0) * 2;   // v2
const     auto Pi = acos(x) * 2;   // v3
constexpr auto Pi = acos(x) * 2;   // v4
```

### Простыми словами
- **`const`** значит «после создания менять нельзя». Но *когда* посчитано значение, `const` не говорит: может при компиляции, может при запуске.
- **`constexpr`** значит «значение обязано быть посчитано при компиляции». Если компилятор так не может, будет ошибка.

Аналогия: `const` — это записка «не трогать». `constexpr` — «это число должно быть известно ещё до начала работы, потому что его напечатают на упаковке».

### Что получилось

| Вариант | Компиляция | Значение считается |
|---|---|---|
| v1 `const ... acos(0)` | ок | при запуске |
| v2 `constexpr ... acos(0)` | ок | **при компиляции** |
| v3 `const ... acos(x)` | ок | при запуске |
| v4 `constexpr ... acos(x)` | **ошибка** | — |

Ошибка в v4: `the value of 'x' is not usable in a constant expression`. Переменная `x` обычная (не `constexpr`), её значение компилятор «не знает» заранее, хотя мы и записали туда 0. Поэтому посчитать `acos(x)` при компиляции нельзя.

### Как проверить, что константа именно «времени компиляции»
Добавить `static_assert(Pi > 3, "");`. Это проверка, которая работает **только при компиляции**. Если значение неизвестно компилятору, она не пройдёт. Так и вышло: прошёл только v2.

### Подвох
`acos` по стандарту C++ **не** `constexpr`. В v2 всё собралось только потому, что g++ умеет считать `acos` при компиляции (это его расширение). С другим компилятором строка v2 может не собраться.

**Ответ:** константа этапа трансляции объявлена только в варианте 2.

## Задание 2. Нужны ли вложенные фигурные скобки?

### Код
С фигурными скобками:

```cpp
int main() {
    {
        int x, y;
        cin >> x >> y;
        cout << x + y << endl;
    }
    {
        double x, y;
        cin >> x >> y;
        cout << x + y << endl;
    }
}
```

Без них (`no_braces.cpp`): те же `int x, y;` и `double x, y;`, но подряд, прямо в теле `main`.

### Простыми словами
Фигурные скобки `{ }` создают **блок**. Это как отдельная комната: что объявили внутри, то снаружи не видно и после выхода исчезает.

- Без скобок обе пары `x, y` оказываются **в одной комнате**. Два жильца с одним именем в одной комнате не уживутся. Даже если типы разные (`int` и `double`), это всё равно ошибка: `conflicting declaration 'double x'`.
- Со скобками это две разные комнаты. В каждой свой `x`, и они друг другу не мешают.

### Результат
Ввод `1 2` даёт `3`, ввод `1.5 2.25` даёт `3.75`.

**Ответ:** да, скобки нужны (или пришлось бы придумывать другие имена).

## Задание 3. Два вложенных цикла по `i`

### Код
```cpp
int s = 0;
for (int i = 0; i < 4; i++) {
    for (int i = 0; i < 3; i++) {
        s += i;
    }
}
std::cout << s << std::endl;
```

В условии не было `;` после `int s = 0`, автор его добавил.

### Простыми словами
Каждый `for` создаёт свой блок, а переменная `i` из его заголовка живёт только внутри этого цикла. Внутренний `int i` — **новая** переменная, которая «заслоняет» внешнюю с тем же именем (это называется *shadowing*, затенение). Пока идёт внутренний цикл, внешнего `i` не видно, но он никуда не делся и не меняется.

Считаем:

- Внутренний цикл: `i = 0, 1, 2` → добавляет `0 + 1 + 2 = 3`.
- Внешний цикл крутится 4 раза (`i = 0, 1, 2, 3`), и внутренний его счётчик не трогает.
- Итого: `4 * 3 = 12`.

**Ответ: 12.** Если скомпилировать с `-Wshadow`, компилятор предупредит: `declaration of 'i' shadows a previous local`. Это не ошибка, просто намёк, что так писать рискованно.

## Задание 5. Свой пример с несколькими пространствами имён

### Код (сокращённо)
```cpp
namespace geom {
    const double pi = 3.14159265;
    double circle_area(double r) { return pi * r * r; }
    namespace util {
        double square(double x) { return x * x; }
    }
}

namespace phys {
    const double pi = 3.0;          // то же имя, другой объект
    double kinetic(double m, double v) { return m * geom::util::square(v) / 2; }
}

int main() {
    std::cout << geom::pi << " " << phys::pi << std::endl;    // 3.14159 3
    std::cout << geom::circle_area(2) << std::endl;           // 12.5664
    std::cout << phys::kinetic(2, 3) << std::endl;            // 9
    using geom::circle_area;                                  // только одно имя
    std::cout << circle_area(1) << std::endl;                 // 3.14159
    using namespace phys;                                     // все имена пространства
    std::cout << kinetic(1, 4) << std::endl;                  // 8
}
```

### Простыми словами
**Пространство имён** — это «папка» для имён. В двух разных папках могут лежать файлы с одинаковым названием.

- `geom::pi` и `phys::pi` — две разные переменные с одним именем `pi`. Конфликта нет, потому что полный адрес разный.
- `geom::util` — папка внутри папки (вложенное пространство). Доступ: `geom::util::square`.
- Функция `phys::kinetic` берёт `square` из соседнего пространства, написав полное имя.
- В `main` показаны три способа обращаться к именам:
  1. Полное имя: `geom::pi`. Самый явный.
  2. `using geom::circle_area;` — «из `geom` хочу короткое имя только для `circle_area`».
  3. `using namespace phys;` — «открой всю папку `phys`, пиши имена без префикса».

Проверим числа: `kinetic(2, 3) = 2 * 3² / 2 = 9`, `kinetic(1, 4) = 1 * 16 / 2 = 8`, `circle_area(2) = 3.14159265 * 4 ≈ 12.5664`. Всё совпадает с выводом.

> После `using namespace phys;` писать просто `pi` уже нельзя: если открыты и `geom`, и `phys` одновременно, `pi` станет неоднозначным. В программе этого нет, но это типичная ловушка.

## Задание 6. Медленный обмен строк

### Условие
Программа 1 000 000 раз обменивает две строки по 100 000 символов через третью. Надо замерить время, попробовать `swap` и найти ошибку.

### Код
Три файла, отличается только тело цикла:

```cpp
string a(100000, 'a');
string b(100000, 'b');
for (int i = 0; i < 1000000; i++) {
    // 1) исходный (swap_slow):
    string c(a);  a = b;  b = c;

    // 2) swap_std:
    swap(a, b);

    // 3) swap_move:
    string c(move(a));  a = move(b);  b = move(c);
}
```

### Простыми словами
Обмен двух стаканов воды через третий: можно перелить воду три раза, а можно просто **поменять местами сами стаканы**.

- **Исходный вариант** — переливание. `string c(a)` создаёт копию, `a = b` копирует, `b = c` копирует. Это **три копирования по 100 КБ** на каждый шаг, плюс создание и удаление буфера для `c`. Умножаем на миллион шагов: десятки гигабайт копий.
- **`swap(a, b)`** — просто меняет местами внутренние указатели строк («на какой кусок памяти смотрит строка»). Сами символы не двигаются. Скорость не зависит от длины строки.
- **`move`** — говорит «можешь забрать содержимое у `a`, оно мне больше не нужно». Строка `c` забирает указатель на данные, а не копирует их. Эффект такой же.

### Время (`g++ -O0`)

| Вариант | Автор README | Мой повторный запуск |
|---|---|---|
| копирование (исходный) | 7.8 с | 6.2 с |
| `swap(a, b)` | 0.009 с | 0.005 с |
| `move` | 0.015 с | 0.012 с |

Абсолютные цифры зависят от компьютера, но разница в **сотни–тысячи раз** видна везде.

**Ошибка исходной программы:** обмен выполняется копированием. **Исправление:** `swap(a, b);`.

## Задание 7. Что делает программа с `id`

### Код
```python
a = 'Hello world'
print(a, id(a))
b = a
print(b, id(b))
a += ' and goodbye'
print(a, id(a))
print(b, id(b))
```

### Вывод (числа у вас будут другие)
```
Hello world 140609231530992
Hello world 140609231530992
Hello world and goodbye 140609231535152
Hello world 140609231530992
```

### Простыми словами
В Python переменная — это **ярлык (ссылка)**, привязанный к объекту в памяти. `id()` показывает номер этого объекта (в CPython это его адрес в памяти).

1. `a = 'Hello world'` — создан объект-строка, на него вешаем ярлык `a`.
2. `b = a` — новый объект **не создаётся**, просто вешаем на тот же объект второй ярлык `b`. Поэтому `id` одинаковые.
3. `a += ' and goodbye'` — строки в Python **неизменяемые** (immutable). Изменить старую строку нельзя, поэтому создаётся **новая** строка `'Hello world and goodbye'`, и ярлык `a` переклеивается на неё.
4. Ярлык `b` остался на старой строке, её `id` не изменился.

**Главная мысль:** одинаковый `id` значит «это один и тот же объект», а не «значения похожи».

## Задание 8. `b = a` и `b = a[:]` для строки

### Код
```python
a = 'Hello world'
b = a
c = a[:]
print(id(a), id(b), id(c), b is a, c is a)   # три одинаковых id, True True

l = [1, 2, 3]
m = l
n = l[:]
print(id(l), id(m), id(n), m is l, n is l)   # id(n) другой, True False
```

### Простыми словами
- `a[:]` — «срез от начала до конца», то есть «копия всей последовательности».
- **Для строки** копия не нужна: строку всё равно нельзя изменить, значит двум ярлыкам безопасно смотреть на один объект. Python это знает и возвращает **тот же самый объект**. Разницы между `b = a` и `b = a[:]` нет.
- **Для списка** список изменяемый. Если бы `n` и `l` смотрели на один объект, то `n.append(4)` изменил бы и `l`. Поэтому `l[:]` создаёт **настоящую новую копию** (с другим `id`), а `m = l` остаётся просто вторым ярлыком на тот же список.

**Ответ:** для строки разницы нет, для списка есть.

## Задание 9. 2600 переменных `a0..a99, b0..b99, ..., z0..z99`

### Код
```python
import string

k = 1
for letter in string.ascii_lowercase:      # 'a', 'b', ..., 'z'
    for i in range(100):                    # 0..99
        globals()[letter + str(i)] = k      # создаём переменную с таким именем
        k += 1

print(a0, a99, b0, z98, z99)                # 1 100 101 2599 2600
print(len([v for v in globals() if len(v) <= 3 and v[0] in string.ascii_lowercase and v[1:].isdigit()]))   # 2600
```

### Простыми словами
Руками писать `a0 = 1`, `a1 = 2`, ... 2600 раз нереально. Но в Python все глобальные переменные хранятся в обычном **словаре**: имя → значение. Его можно получить функцией `globals()`.

Значит, строка `globals()['a0'] = 1` делает то же самое, что `a0 = 1`. Остаётся только в цикле собирать имя из буквы и числа: `'a' + str(0)` → `'a0'`.

- Внешний цикл идёт по буквам, внутренний — по числам 0–99.
- Счётчик `k` растёт на 1 с каждой переменной: `a0 = 1`, ..., `a99 = 100`, `b0 = 101`, ..., `z99 = 2600`.

Вторая строка с `print` проверяет, что всего создано ровно 2600 имён нужного вида (в `globals()` есть и служебные имена вроде `string` или `k`, поэтому они отфильтрованы).

## Задание 10 (*). Работает ли `a, b = b, a` для списков?

### Код
```python
import time

for n in (10, 10**5, 10**7):
    a = list(range(n))
    b = list(range(n, 2 * n))
    ida, idb = id(a), id(b)
    a, b = b, a
    print(n, 'id обменялись:', id(a) == idb and id(b) == ida)
    t = time.perf_counter()
    for _ in range(1000):
        a, b = b, a
    t = time.perf_counter() - t
    print('   время на 1000 обменов: %.6f c' % t)
```

### Вывод
```
10 id обменялись: True
   время на 1000 обменов: 0.000052 c
100000 id обменялись: True
   время на 1000 обменов: 0.000048 c
10000000 id обменялись: True
   время на 1000 обменов: 0.000082 c
```

### Простыми словами
**Да, работает.** Как это устроено:

1. Сначала Python полностью вычисляет **правую часть** `b, a` — берёт две ссылки (на список `b` и на список `a`) и складывает их в пару.
2. Потом присваивает слева направо: `a` теперь смотрит на бывший `b`, а `b` на бывший `a`.

Сами элементы списков **не копируются**, переставляются только два «ярлыка». Поэтому время почти не зависит от размера: и для 10 элементов, и для 10 миллионов 1000 обменов занимают сотые доли миллисекунды (небольшие различия — это шум измерения).

Проверка `id(a) == idb and id(b) == ida` даёт `True`: объекты-списки действительно поменялись местами, а не были перезаписаны.

Это тот же приём, что `swap` из задания 6 (меняем ссылки, а не данные), только в Python он встроен в язык.

## Задание 11 (*). Функция `sumint()`: сумма всех целочисленных переменных

### Код
```python
import sys

def sumint():
    s = 0
    for value in vars(sys.modules['__main__']).values():
        if type(value) is int:
            s += value
    return s
```

### Простыми словами
Когда вы в IDLE пишете `a = 10`, эта переменная записывается в словарь главного модуля `__main__`. Достать его можно через `sys.modules['__main__']`, а `vars(...)` превращает модуль в словарь «имя → значение».

Функция идёт по всем значениям, и если значение — целое число, прибавляет к сумме.

**Почему `type(value) is int`, а не `isinstance(value, int)`.** В Python `bool` (`True` / `False`) — это подкласс `int`. `isinstance(True, int)` вернёт `True`, и `True` посчиталось бы как 1. Проверка `type(...) is int` принимает только «чистые» целые.

### Пример из задания
```python
a = 10; b = 1.5; c = 15; d = 'hello'
sumint()   # 25
```
`10 + 15 = 25`: `1.5` (float) и `'hello'` (строка) пропущены.

> Мелочь: папка `__pycache__` с файлом `.pyc` в архиве создана автоматически Python-ом, это не часть решения.

## Задание 12 (*). Как переменные лежат в памяти C++

### Код (по частям)
Вспомогательная функция печатает адрес любой переменной:

```cpp
template <class T>
unsigned long long addr(T &t) { return reinterpret_cast<unsigned long long>(&t); }
```

**Часть 1.** Разные типы в одном блоке: `char c; short sh; int i; long long ll; double d; long double ld;`

**Часть 2.** Три отдельных блока `{ int x; }`, `{ int y; }`, `{ double z; }` подряд.

**Часть 3.** Три `std::string`: смотрим адрес самой переменной и адрес её данных (`s.data()`) до и после присваивания.

### Что я получил

**Часть 1.** Смотрим на разность соседних адресов:

| Переменная | Адрес (последние цифры) | Разница до следующей | Размер типа |
|---|---|---|---|
| `c` | ...857 | 1 | 1 байт |
| `sh` | ...858 | 2 | 2 байта |
| `i` | ...860 | 4 | 4 байта |
| `ll` | ...864 | 8 | 8 байт |
| `d` | ...872 | **24** | 8 байт |
| `ld` | ...896 | | 16 байт |

Переменные идут подряд, и каждая занимает ровно свой размер. Исключение — `long double`: для него адрес должен быть **кратен 16** (выравнивание), поэтому после `d` образуется 16 байт пустого места (8 + 16 = 24). На `-O2` компилятор расставляет плотнее, и зазора нет.

> Порядок размещения стандарт не гарантирует. Это поведение g++, другой компилятор может разложить иначе.

**Часть 2.** Адрес переменной во всех трёх блоках **один и тот же** (в моём запуске `...896` три раза подряд, хотя типы разные: `int`, `int`, `double`). Когда блок заканчивается, переменная удаляется и место в стеке освобождается, следующий блок занимает это же место. Аналогия: три гостя по очереди селятся в один и тот же номер гостиницы.

**Часть 3.**

- `sizeof(std::string)` всегда **32 байта**, при любой длине строки. Внутри объекта хранятся указатель на данные, размер и небольшой встроенный буфер на 16 байт.
- Адрес самой переменной `s1`, `s2`, `s3` **не меняется** после присваивания.
- Меняется только адрес **данных** `s.data()`:
  - короткая строка `"hi"` помещается во встроенный буфер: `s1.data()` лежит прямо внутри объекта (в моём запуске адрес ровно на 16 байт больше адреса `s1`);
  - строка из 100 000 символов не помещается, и её буфер выделяется в **куче**. Адрес `s3.data()` (`947...`) совсем не похож на адреса стека (`1407...`).

Образно: переменная — это «визитка» фиксированного размера на своём месте в стеке, а длинный текст хранится в другом месте (куче), и визитка просто указывает на него.

**Влияние оптимизации** (`-O0` против `-O2`): почти нет. Заметно только то, как плотно упаковано перед `long double`.

## Шпаргалка: главные идеи лабы

| Тема | Идея в одной фразе |
|---|---|
| `const` vs `constexpr` | `const` — «нельзя менять», `constexpr` — «посчитано при компиляции» |
| Блоки `{ }` | Переменная живёт до закрывающей скобки; в одном блоке повторять имя нельзя |
| Затенение (shadowing) | Внутренняя переменная с тем же именем прячет внешнюю, но не меняет её |
| `namespace` | «Папка» для имён, позволяет иметь одинаковые имена в разных местах |
| Копирование vs перемещение | Копия двигает все данные, `swap` и `move` меняют только указатели |
| Python: переменная | Это ярлык на объект; `id` одинаковый — объект один и тот же |
| Неизменяемые объекты | Строку «изменить» нельзя, создаётся новая |
| `a, b = b, a` | Меняет две ссылки, данные не копируются, время не зависит от размера |
| `globals()` | Словарь всех глобальных переменных: можно создавать имена в цикле |
| Память C++ | Переменные в стеке лежат по порядку с выравниванием; освобождённое место переиспользуется |
