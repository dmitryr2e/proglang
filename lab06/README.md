### Задание 1 **(2)**
*Проверьте четыре варианта строки с объявлением* `Pi` *(const/constexpr, acos(0)/acos(x)). В каких вариантах объявляется константа этапа трансляции?*

Файлы `task01/v1.cpp` ... `v4.cpp`.

| Вариант | Результат |
|---|---|
| `const auto Pi=acos(0)*2;` | компилируется, `Pi` --- константный объект, значение считается при выполнении |
| `constexpr auto Pi=acos(0)*2;` | компилируется, константа этапа трансляции |
| `const auto Pi=acos(x)*2;` | компилируется, `x` --- обычная переменная, значение считается при выполнении |
| `constexpr auto Pi=acos(x)*2;` | **ошибка**: `the value of 'x' is not usable in a constant expression` |

Чтобы проверить, где значение известно при компиляции, я добавил `static_assert(Pi>3, "")`. Он прошел только в варианте 2, в вариантах 1 и 3 была ошибка `non-constant condition`. Значит, константа этапа трансляции объявлена только во втором варианте. `const` только запрещает менять объект, а `constexpr` требует, чтобы значение вычислялось при компиляции. В варианте 4 это невозможно, потому что `x` не `constexpr`.
Вариант 2 собрался, потому что g++ умеет вычислять `acos` при компиляции (расширение GCC). По стандарту `acos` не `constexpr`, поэтому с другим компилятором такая строка может не собраться.

### Задание 2 **(2)**
*Нужны ли в программе вложенные фигурные скобки?*

Файлы `task02/with_braces.cpp`, `task02/no_braces.cpp`.

Нужны. Без них `int x, y;` и `double x, y;` оказываются в одном блоке (в теле `main`), а повторное объявление переменной в одном блоке запрещено, даже если тип другой. g++ выдает `conflicting declaration 'double x'`. Фигурные скобки создают два отдельных блока: переменные первого блока удаляются при выходе из него, и во втором блоке имена `x`, `y` объявляются заново. Без скобок можно было бы просто взять другие имена. С двумя блоками программа работает (ввод `1 2` дает `3`, ввод `1.5 2.25` дает `3.75`).

### Задание 3 **(2)**
*Проверьте работу фрагмента с двумя вложенными циклами по* `i`*. Каким вычислениями получен ответ?*

Файл `task03/nested_i.cpp`.

Программа выводит **12**. Цикл `for` создает собственный блок, поэтому внутренний `int i` объявляется заново и вытесняет внешний `i` (с `-Wshadow` есть предупреждение `shadows a previous local`). Внутренний цикл выполняется для `i = 0, 1, 2` и добавляет к `s` значение `0+1+2 = 3`. Внешний `i` внутренним циклом не меняется, и внешний цикл делает 4 итерации (`i = 0..3`). Итого `s = 4*3 = 12`.

### Задание 6 **(2)**
*Программа 1000000 раз обменивает две строки по 100000 символов через третью. Проверить время, попробовать* `swap`*, найти ошибку.*

Файлы `task06/swap_slow.cpp`, `swap_std.cpp`, `swap_move.cpp` (сборка `g++ -O0`).

| Вариант | Время |
|---|---|
| исходный (`c(a); a=b; b=c;`) | 7.8 с |
| `swap(a, b)` | 0.009 с |
| `c(move(a)); a=move(b); b=move(c);` | 0.015 с |

Ошибка исходной программы в том, что обмен делается копированием. На каждой итерации строка копируется три раза (`c(a)`, `a = b`, `b = c`), то есть копируется по 100 КБ данных, и еще создается и удаляется буфер строки `c`. `swap` и `move` только обмениваются внутренними указателями строк и не копируют символы, поэтому время почти не зависит от длины строк. Исправленная программа: `swap(a, b);` в цикле.

### Задание 7 **(2)**
*Объясните работу программы с* `id`*.*

Файл `task07/ids.py`. Вывод:
```
Hello world 140218773679088
Hello world 140218773679088
Hello world and goodbye 140218773683248
Hello world 140218773679088
```
Первая строка создается при выполнении `a = 'Hello world'`, и `a` получает ссылку на нее. `b = a` копирует только ссылку, новой строки нет, поэтому `id` одинаковые. Строки в Python неизменяемые, поэтому `a += ' and goodbye'` не меняет старую строку, а создает новую `'Hello world and goodbye'` и записывает в `a` ссылку на нее. `b` продолжает ссылаться на старую строку, и ее `id` не изменился. Значение `id` --- число, однозначно определяющее объект (в CPython это адрес в памяти). Его используют только для сравнения, одинаковый `id` означает один и тот же объект.

### Задание 8 **(2)**
*Есть ли разница между* `b = a` *и* `b = a[:]` *для строки?*

Файл `task08/slice.py`. Для строки разницы нет: `a`, `b = a` и `c = a[:]` имеют один и тот же `id` (`c is a` дает `True`). Строка неизменяемая, поэтому для среза целиком копия не нужна и возвращается тот же объект. Для списка разница есть: `l[:]` создает новый список с другим `id`, а `m = l` просто вторая ссылка на тот же список.

### Задание 10 **(*2)**
*Будет ли работать* `a,b=b,a` *для списков? Зависит ли время от размера?*

Файл `task10/swap.py`. Работает. Сначала целиком вычисляется правая часть: из ссылок на `b` и `a` собирается пара (в байткоде `LOAD b`, `LOAD a`, `SWAP`). Потом присваивания выполняются слева направо: `a` получает ссылку на старый `b`, а `b` --- на старый `a`. Элементы списков не копируются, меняются только две ссылки. Поэтому время не зависит от размера: 1000 обменов занимают около 0.00005 с и для списков из 10, и из 10^5, и из 10^7 элементов. Проверка `id` показала, что объекты-списки поменялись местами.

### Задание 12 **(*5)**
*Исследовать расположение переменных в памяти C++.*

Файл `task12/addr.cpp`, запуск с `-O0` и `-O2`. Абсолютные адреса меняются от запуска к запуску (ASLR), поэтому сравниваю разности.

1. **Переменные разных типов в одном блоке.** Адреса идут по порядку объявления. Разность адресов соседних переменных равна размеру предыдущей: `c`→`sh` 1 байт (`char`), `sh`→`i` 2 байта (`short`), `i`→`ll` 4 байта (`int`), `ll`→`d` 8 байт (`long long`). Исключение --- `long double` (16 байт): адрес должен быть кратен 16, поэтому после `double` разница 24 на `-O0` (8 байт `double` и 16 байт пустого места) и 8 на `-O2` (пустого места нет). Порядок размещения стандартом не гарантируется, так что другой компилятор может разложить переменные иначе.
2. **Последовательные блоки.** Переменные `x`, `y` (int) и `z` (double) из трех разных блоков имеют **один и тот же адрес** и на `-O0`, и на `-O2`. После выхода из блока переменная удалена, ее место в стеке свободно и используется следующим блоком.
3. **Строки.** `sizeof(std::string)` всегда 32 (в libstdc++ это указатель, размер и внутренний буфер на 16 байт), независимо от длины строки. Адрес самой переменной при присваивании не меняется. Меняется только адрес данных `s.data()`: у короткой строки `"hi"` символы лежат внутри самого объекта (`s1.data()` на 16 байт больше адреса `s1`), а у строки из 100000 символов буфер выделен в куче (адрес сильно отличается от адресов стека). То есть переменная остается на месте, а перемещается только буфер с данными.

Уровень оптимизации на этих результатах почти не сказывается. Различие только в выравнивании перед `long double`.
