### Задание 1 **(3)**
*Составьте глоссарий из определений лекции. Проверка отчета будет включать 
проверку знания определений*

* **Тип в программировании** — атрибут объекта данных, задающий множество допустимых значений и методы для работы с ними.

* **Статическая типизация** — язык программирования обладает статической типизацией, если тип объекта данных определяется в момент трансляции. Тип литералов определяется по записи литерала, тип переменных и именованных констант — по объявлению, тип результатов выражений — по оператору и типу операндов.

* **Динамическая типизация** — язык программирования обладает динамической типизацией, если тип объекта данных определяется на этапе выполнения программы в момент создания или присваивания значения.
  Плюсы: позволяет писать более обобщенные алгоритмы, текст программы выглядит компактнее.
  Минусы: снижается быстродействие, типизация не используется для раннего обнаружения ошибок.

* **Неявная типизация** (утиная) — тип определяется на этапе трансляции автоматически по тексту программы (например, `auto` в C++). Идея: «если птица ходит как утка, плавает как утка и крякает как утка, я называю эту птицу уткой».

* **Явное преобразование типа** — преобразование типа (метод, преобразующий значение одного типа в такое же или близкое значение другого типа) называется явным, если оно указано в программе в виде вызова функции или в виде операции (например, `static_cast<long long>(d)` в C++ или `int(a)` в Python).

* **Неявное преобразование типа** — преобразование типа называется неявным, если оно не присутствует в программе в виде конкретного указания, однако транслятор сам подставляет требуемый метод преобразования.

* **Сильная типизация** — язык программирования не содержит (почти не содержит) правил неявного преобразования типа.

* **Слабая типизация** — язык программирования содержит большое число правил неявного преобразования типа, допускает каламбуры типизации.

Дополнительно к определениям, которые нужны для этих терминов:

* **Каламбур типизации** — ситуация, когда одна ячейка данных рассматривается как две переменные разных типов.
* **Ошибка согласования типа** (type error) — использование значения одного типа в контексте другого типа. К ним относятся, в частности, ошибки из-за неявных преобразований типов или каламбуров типизации.
* **Типобезопасный язык** — язык, на котором в принципе невозможно написать программу, в которой возникают недиагностируемые ошибки согласования типов.

Сильная и слабая типизация — это не две разные категории, а качественная характеристика: можно сказать, что типизация одного языка более сильная, чем у другого.

### Задание 2 **(3)**

*Запишите правила неявного преобразования типов в языке С++*

Между всеми базовыми типами C++ существуют неявные преобразования.

*Преобразования при присваивании*

* При присваивании значение правого операнда приводится к типу левого операнда.
* При вызове функции фактический параметр приводится к типу формального параметра.
* Из вещественного типа в целочисленный: отсекается дробная часть (`int x = 3.14;` даст 3).
* В `bool`: 0 → `false`, любое другое значение → `true`.
* Из `bool`: `false` → 0, `true` → 1.
* С символьными типами: преобразование идет по коду символа (`'a'` → 97).

*Преобразования при арифметических действиях*

Так же работают операции сравнения.

1. Если длины обоих типов меньше `int`, то оба операнда преобразуются к `int`.
2. Если типы разной длины, то меньший преобразуется к большему.
3. Если типы равной длины, один знаковый, а другой беззнаковый, то знаковый приводится к беззнаковому.
4. Если один операнд целый, а другой вещественный, то целый приводится к вещественному.

*Преобразования с логическими значениями*

* Результат условного выражения в инструкциях ветвления и цикла (`if`, `while`, `for`) приводится к логическому типу.
* Если оператор требует логического значения, то его операнды приводятся к логическому типу (операции `&&`, `||`, `!`).
* Если оператор требует целого числа, то операнд приводится к целому (суффиксный инкремент и декремент, сдвиги, остаток от деления, битовые операции). Поэтому `bool` в таких операциях превращается в `int`.
* Результат сравнения имеет тип `bool`, но в арифметике он снова превращается в число: `'a' + true` даст 98, а `3 < 2 < 1` вычисляется как `(3 < 2) < 1` = `false < 1` = `0 < 1` = `true`.

### Задание 3 **(2)**

*Языки C++ и Java имеют похожий синтаксис, однако
язык С++ относят к языкам со слабой статической типизацией, а Java - с сильной статической типизацией.
Приведите примеры, показывающие это различие. Для этого вам надо подобрать несколько близких по смыслу фрагментов программ,
которые будут транслироваться в С++, но вызывать ошибку согласования типов в Java.*

*Записанные программы сохраните в папке с номером задания. В отчет запишите пояснения к работе программам.*

Программы лежат в папке `3`. Для каждого примера есть пара файлов: `exN.cpp` и `exN.java`. Все файлы `.cpp` компилируются (g++) и запускаются, а все файлы `.java` дают ошибку при трансляции.

**Пример 1 (ex1). Вещественное число присваивается целой переменной.**
```cpp
int x = 3.14;
```
В C++ работает правило неявного преобразования при присваивании: значение правого операнда приводится к типу левого, дробная часть отсекается, программа выводит 3. В Java такая запись даст ошибку `incompatible types: possible lossy conversion from double to int`, потому что Java не делает неявных преобразований с потерей информации. Нужно писать явно: `int x = (int) 3.14;`.

**Пример 2 (ex2). Целое число в условии цикла.**
``cpp
int n = 3;
while (n) { ... n--; }
```
В C++ результат условного выражения приводится к логическому типу (0 — `false`, остальные — `true`), программа выводит `3 2 1`. В Java условие должно иметь тип `boolean`, поэтому будет ошибка `int cannot be converted to boolean`. Нужно писать `while (n != 0)`.

**Пример 3 (ex3). Преобразования между `int` и `bool`.**
```cpp
bool b = 5;
int i = true;
```
В C++ 5 превращается в `true`, а `true` в 1, программа выводит `1 1`. В Java `boolean` и `int` вообще несовместимы, обе строки дают ошибку.

**Пример 4 (ex4). Длинное целое присваивается короткому.**
```cpp
long long big = 5000000000LL;
int small = big;
```
В C++ происходит неявное сужение, старшие биты отбрасываются и получается неожиданное число 705032704. Это как раз тот случай, когда ошибка есть, а компилятор ее не диагностирует (в этом смысле C++ не типобезопасен). В Java ошибка `possible lossy conversion from long to int`.

**Пример 5 (ex5). Вещественный аргумент при вызове функции с целым параметром.**
```cpp
void f(int a) { ... }
f(2.9);
```
В C++ фактический параметр неявно приводится к типу формального, выводится 2. В Java вызов не проходит трансляцию: метод `f` нельзя применить к аргументу типа `double`.

Вывод: в C++ много правил неявного преобразования (между числами, между числами и `bool`, с потерей информации), поэтому типизация слабая. В Java почти все такие преобразования нужно указывать явно, поэтому типизация сильная. Оба языка при этом статические, потому что типы проверяются при трансляции.

*Используя* **typeid**, *найдите типы переменных* **a** и **b**. *Объясните результат.*

Тип переменных, объявленных через `auto`, выводится в момент трансляции по типу выражения справа, то есть это статическая типизация.

4294967295

Ошибка исчезла: короткий беззнаковый тип не «заражает» выражение беззнаковостью.

### Задание 7 **(2)**

*Рассмотрите следующий фрагмент программы.*
```
int x = 7, y = 4;
long double d = 0.25;
cout << (x / y) / d << endl;
cout << (x / d) / y << endl;
long a = 200000, b = 200000;
long long c = 200000;
std::cout << (a * b) * c << std::endl;
std::cout << a * (b * c) << std::endl;
```
*Почему изменения порядка действий приводит
к изменению результата? Объясните работу этой программы, используя правила
неявного преобразования типов*

Программы лежат в папке `7`: `main.cpp` (исходный фрагмент) и `main_int.cpp` (вариант с `int`, объяснение ниже). Вывод `main.cpp` на моей машине:
```
4
7
8000000000000000
8000000000000000
sizeof(long) = 8
```

**Первая пара строк.**

* `(x / y) / d`: сначала `x / y` — оба операнда `int`, поэтому деление целочисленное: `7 / 4 = 1`, дробная часть потеряна. Затем `1 / d`: целый операнд приводится к вещественному (`long double`), получается `1 / 0.25 = 4`.
* `(x / d) / y`: сначала `x / d` — `x` приводится к `long double`, деление вещественное: `7 / 0.25 = 28`. Затем `28 / y`, `y` приводится к `long double`, результат `7`. Это верный ответ.

Порядок действий изменил результат потому, что тип операции определяется типами операндов. В первом случае целочисленное деление выполнилось до приведения к вещественному типу и потеряло дробную часть.

**Вторая пара строк.**

* `(a * b) * c`: сначала `a * b` — оба `long`, умножение выполняется в типе `long`. Только потом результат приводится к `long long` для умножения на `c`.
* `a * (b * c)`: сначала `b * c` — `b` приводится к `long long`, умножение выполняется в `long long`. Потом `a` приводится к `long long`.

Правильный результат `200000^3 = 8 * 10^15`. Разница между вариантами в том, где произойдет переполнение: в первом варианте произведение `a * b = 4 * 10^10` считается в типе `long`, во втором — в `long long`.

На моей машине (Linux, 64 бита) `long` занимает 8 байт (`sizeof(long) = 8`), `4 * 10^10` в него помещается, поэтому оба результата одинаковы. Если `long` занимает 4 байта (Windows, 32-битные системы), то `a * b` переполняется. Чтобы показать эффект на любой платформе, в `main_int.cpp` я заменил `long` на `int`. Вывод:
```
269058867200000
8000000000000000
```
Здесь `a * b = 40000000000` не помещается в 32 бита и превращается в `40000000000 mod 2^32 = 1345294336`, умножение на `c` дает `269058867200000`. Во втором варианте `b * c` считается в `long long`, переполнения нет и получается верное `8000000000000000`. (Переполнение знакового типа в стандарте C++ — неопределенное поведение, здесь оно проявилось как «заворачивание» числа.)

### Задание 8 **(2)**

*Для каких значений целочисленных переменных* **x**, **y** ,**z** *результатом
вычисления следующего выражения будет истина? Перечислите* **все** *случаи.
Объясните работу этой программы, используя правила неявного преобразования типов*

```
(x == y) + (x == z) == true
```

*Записанные программы сохраните в папке с номером задания.*

Программа лежит в папке `8` (`main.cpp`).

Объяснение по шагам:

1. Приоритет операции `+` выше, чем у `==`, поэтому выражение читается как `((x == y) + (x == z)) == true`.
2. `x == y` и `x == z` имеют тип `bool`. Оператор `+` требует чисел, поэтому оба `bool` приводятся к `int` (`false` → 0, `true` → 1). Сумма — `int` со значением 0, 1 или 2.
3. Дальше сравнивается `int` с `true`. Длина `bool` меньше `int`, поэтому `true` приводится к `int` и становится 1.
4. Итого выражение истинно тогда и только тогда, когда сумма равна 1, то есть **ровно одно** из равенств `x == y`, `x == z` истинно.

Все случаи:

* `x == y` и `x != z` (то есть `y = x`, а `z` — любое число, не равное `x`);
* `x == z` и `x != y` (то есть `z = x`, а `y` — любое число, не равное `x`).

Не подходят:

* `x == y == z` (все три равны): сумма равна 2, а `2 == 1` ложно;
* `x` не равно ни `y`, ни `z` (в том числе когда `y == z != x`): сумма равна 0.

Проверка в программе: перебор всех троек из диапазона от -3 до 3 нашел 84 подходящие тройки. Формула тоже дает 84: 7 · 6 = 42 тройки для первого случая и 42 для второго, пересечения нет, так как `y = x` и `z = x` одновременно означало бы сумму 2.

**Python.** Это цепочечное сравнение: `x == y == z` означает `x == y and y == z` (`y` вычисляется один раз). Выражение истинно тогда и только тогда, когда все три числа равны. Результаты: `(5, 5, 5)` → `True`, `(1, 1, 1)` → `True`, `(1, 2, 0)` → `False`, `(1, 2, 3)` → `False`, `(1, 1, 2)` → `False`.

**Java.** Операции `==` вычисляются слева направо, то есть `(x == y) == z`. Результат `x == y` имеет тип `boolean`, и его сравнивают с `int` `z`. Неявных преобразований между `boolean` и `int` в Java нет, поэтому программа не транслируется: `incomparable types: boolean and int`. Чтобы проверить равенство трех чисел, нужно писать `x == y && y == z`.

**C++.** Порядок тоже слева направо: `(x == y) == z`. Результат `x == y` имеет тип `bool`, при сравнении с `int` он приводится к `int` (`true` → 1, `false` → 0). Поэтому выражение истинно, если (`x == y` и `z == 1`) или (`x != y` и `z == 0`). Результаты:

* `x = y = z = 5`: `(5 == 5) == 5` → `1 == 5` → `0` (хотя все числа равны);
* `x = y = z = 1`: `(1 == 1) == 1` → `1 == 1` → `1`;
* `x = 1, y = 2, z = 0`: `(1 == 2) == 0` → `0 == 0` → `1` (хотя числа разные);
* `x = 1, y = 2, z = 3`: `0 == 3` → `0`.

Итого один и тот же текст в трех языках дает три разных результата: в Python — «все равны», в Java — ошибка трансляции, в C++ — бессмысленное для программиста значение без всякого предупреждения. Это тоже показывает разницу в силе типизации.

### Задание 10 **(1)**

*Напишите программу на* **Python** *, демонстрирующую возможность неявного преобразования
строки в логическое значение.*

Программа лежит в папке `10` (`main.py`). Основной фрагмент:
```python
s = input("Введите строку: ")
if s:
    print("Строка непустая, условие истинно")
else:
    print("Строка пустая, условие ложно")
```
Объяснение: в условии `if` строка сама не является логическим значением, но Python неявно приводит ее к `bool` по правилу «пустой объект — `False`, иначе — `True`». Пустая строка `""` дает `False`, любая непустая строка — `True`. Запуск с пустым вводом выводит «Строка пустая, условие ложно», с вводом `hello` — «Строка непустая, условие истинно».

В программе есть еще примеры того же преобразования: `"" or "запасное значение"` (пустая строка ложна, берется второй операнд), `not ""` (дает `True`) и `bool("0")`, `bool("False")`, `bool(" ")` — все три `True`, потому что непустая строка истинна независимо от содержимого. Только `bool("")` дает `False`.
